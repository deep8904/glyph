# Landing / Marketing Direction

## Page job

The landing page must prove that Glyph is where indie games become credible, visible, and collaborative through real build history. It should show the product loop rather than list every feature.

## Recommended narrative

1. **Hero — one sentence and one living Project proof**
   - Outcome-led headline, not “the all-in-one platform.”
   - One primary CTA and one secondary “Explore projects” action.
   - A real Project composition that includes cover media, a Devlog update, contributor identity, and a current stage.
2. **The loop — Build → Document → Discover → Connect → Build again**
   - Five concise steps anchored to one continuing project story.
3. **Project proof**
   - Show how a Project gathers cover media, Devlogs, collaborators, playtests, and milestones.
4. **Devlog as momentum**
   - Reading-first editorial example with visible Developer → Project provenance.
5. **Discovery without engagement bait**
   - Curated and typed results; explain relevance and authorship.
6. **Collaboration and playtesting**
   - Show structured intent, fit, scope, stage, and next action—not generic chat bubbles.
7. **Studios, jams, and events**
   - Treat as extensions of the Project graph; keep this section compact until these workflows are mature.
8. **Permanent product truth / final CTA**
   - Use truthful availability and pricing language. Do not imply paid tiers or upgrade paths unless they actually exist.

## Composition patterns to borrow

- From [Designity](https://dribbble.com/shots/26617849-Designity-Landing-Page): editorial rhythm, warm accents, people and creative work as the visual subject.
- From [Attio Developer Platform](https://dribbble.com/shots/26762768-Attio-Developer-Platform) and [the live Attio page](https://attio.com/platform/developers): compact developer credibility, modular explanation, and real interface proof.
- From [API-as-a-Service](https://dribbble.com/shots/26636553-API-as-a-Service-SaaS-Landing-Page-for-Developer-Platforms): documentation-aware hierarchy and technical clarity.
- From [NotifyHub](https://dribbble.com/shots/25897849-NotifyHub-Notification-Platform-Landing-Page): product structure for complex multi-channel workflows.
- From [AI Clinic](https://dribbble.com/shots/27399872-AI-Clinic-Platform-Landing-Page-Design): custom workflow animation used to explain how the system works.
- From [Linear](https://linear.app/): product UI shown in context and concise outcome-focused sectioning.
- From [Landingfolio](https://www.landingfolio.com/) and [Awwwards](https://www.awwwards.com/): section and art-direction exploration only; validate every idea against Glyph content and usability.

## Landing components

- Global header with restrained navigation and immediate product access.
- Living Project Hero.
- Loop Timeline.
- Devlog Reading Slice.
- Project Proof Strip.
- Creator/Studio Attribution block.
- Collaboration Fit block.
- Playtest Feedback block.
- Curated Project Rail.
- Honest final CTA.

Avoid placing every item in an identical rounded card. Use section composition—scale, alignment, rules, captions, and media—to create hierarchy.

## Responsive behavior

- Mobile hero leads with value, CTA, then project proof; never hide the actual product below decorative art.
- Replace horizontal loop diagrams with a readable vertical sequence.
- Maintain media aspect ratio and focal point.
- Do not shrink desktop type mechanically; recompute line breaks and reading order.
- Keep navigation actions reachable and keyboard-accessible at all widths.

## Motion storyboard

- Hero Project proof: a subtle shared-element handoff between cover, latest Devlog, and contributor state; no autoplay carousel.
- Loop timeline: progress only as the reader enters each step; never trap scroll.
- Project media: minimal depth or crop transition on intentional interaction, not passive pointer movement.
- CTA feedback: immediate pressed state, short confirmation, no elastic overshoot.
- Reduced motion: static composition with clear state labels.

## Landing-specific anti-patterns

- Giant headline plus vague 3D orb.
- Endless logo wall before the product is understood.
- Fake community counts, fake Devlogs, fake game art, or fake testimonials.
- Feature-grid repetition.
- Dark “gaming” skin used as a substitute for art direction.
- Performance-heavy WebGL before the core content is visible.
