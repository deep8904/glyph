## D. Apple-inspired interaction and motion

### Motion

- [Apple HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion) — **OFFICIAL DOC**. Motion should be purposeful, brief, precise, optional, and consistent with a person's action.
- [Designing Fluid Interfaces, WWDC18](https://developer.apple.com/videos/play/wwdc2018/803/) — **OFFICIAL VIDEO**. Key ideas for Glyph: immediate response, spatial continuity, symmetry, gesture-direction hinting, soft boundaries, interruptibility, and prototyping motion with interaction.
- [Enhance your UI animations and transitions, WWDC24](https://developer.apple.com/videos/play/wwdc2024/10145/) — **OFFICIAL VIDEO**. Useful for shared-element/zoom-like transition thinking and state continuity.
- [Apple HIG Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) — **OFFICIAL DOC**. Reduce fast, repetitive, scaling, depth, blur, and peripheral motion when reduced motion is active.

### Layout, type, color, loading, onboarding

- [Apple HIG Layout](https://developer.apple.com/design/human-interface-guidelines/layout) — **OFFICIAL DOC**. Borrow hierarchy, alignment, adaptive layout, reading order, and content legibility.
- [Apple HIG Typography](https://developer.apple.com/design/human-interface-guidelines/typography) — **OFFICIAL DOC**. Borrow legibility, restrained font count, and hierarchy that survives text scaling.
- [Apple HIG Color](https://developer.apple.com/design/human-interface-guidelines/color) — **OFFICIAL DOC**. Use color consistently for meaning and ensure it works across contrast contexts.
- [Apple HIG Loading](https://developer.apple.com/design/human-interface-guidelines/loading) — **OFFICIAL DOC**. Show something promptly, preserve other work, and use determinate progress when duration is known.
- [Apple HIG Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding) — **OFFICIAL DOC**. Keep onboarding fast, optional where possible, interactive, and focused on essential setup.

### What “Apple-like” means for Glyph

- Immediate local feedback, not a glass visual skin.
- One spatial model; selected objects expand or reveal context without teleporting.
- Quiet resting states that respond on interaction.
- Motion tied to cause, direction, and outcome.
- High-quality typography, alignment, and adaptive layouts.
- Respect for input method, accessibility, reduced motion, and user control.

Do **not** copy Liquid Glass as a web theme. Apple's [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) describes an OS-integrated adaptive material; Glyph should borrow the principle of responsive controls and quiet resting state, not simulate lensing everywhere.

## G. Workflow and product-model references

These sources are less about visual style and more about keeping the redesign grounded in coherent product behavior.

### Linear interaction patterns

- [Intro to Linear](https://linear.app/learn/intro-to-linear) — **OFFICIAL DOC**. Reference for calm density and discoverable keyboard acceleration.
- [Command menu](https://linear.app/changelog/2019-12-18-new-command-menu) — **OFFICIAL DOC**. Reference for context-aware commands with visible pointer/touch alternatives.
- [Peek](https://linear.app/docs/peek) — **OFFICIAL DOC**. Reference for inspecting adjacent records without losing list context; useful for Glyph Project, Person, Devlog, and application previews.
- [Board layout](https://linear.app/docs/board-layout) — **OFFICIAL DOC**. Reference only where Glyph objects have meaningful state transitions, such as collaboration applications or playtest rounds.

### itch.io creator and jam patterns

- [Creator getting started](https://itch.io/docs/creators/getting-started) and [page design](https://itch.io/docs/creators/design) — **OFFICIAL DOC**. Project is the public artifact; media, metadata, builds, and creator expression live in a stable shell.
- [Getting indexed](https://itch.io/docs/creators/getting-indexed) — **OFFICIAL DOC**. Useful precedent for keeping publishing separate from discovery eligibility and explaining why work is or is not discoverable.
- [Access control](https://itch.io/docs/creators/access-control) and [limited releases](https://itch.io/docs/creators/limited-releases) — **OFFICIAL DOC**. Useful for playtest and publisher access; a single public/private toggle is not enough.
- [Game jams](https://itch.io/docs/creators/game-jams) — **OFFICIAL DOC**. Useful for explicit submission, rating/review, result, moderator, voter, and late-entry states.

### Curated and associative discovery

- [Cosmos discovery](https://help.cosmos.so/en/articles/11717949-discovery) — **OFFICIAL DOC**. Useful for curated entry points, visually related work, and connected collections beyond a single ranked feed.
- [Behance Moodboards](https://help.behance.net/hc/en-us/articles/204484004-Guide-Moodboards) — **OFFICIAL DOC**. Useful for private/shared collections, scouting lists, playtest queues, and jam inspiration while preserving attribution.
- [The Atrium collaboration case study](https://www.behance.net/gallery/123745661/The-Atrium-Project-Collaboration-Platform) — **PUBLISHER CASE STUDY**. Useful for keeping discussion, learning, and collaboration attached to a Project rather than creating a detached gig marketplace.

### Additional implementation shelves

- [shadcn/ui blocks](https://ui.shadcn.com/blocks) and [components](https://ui.shadcn.com/docs/components) — **COMPONENT SOURCE**. Useful for behavior/composition reconnaissance; do not ship the generic default look or add it if Glyph already has equivalent primitives.
- [Motion Primitives](https://motion-primitives.com/) — **COMPONENT SOURCE**. Use only to study small, composable interaction treatments; adopt one motion vocabulary.
- [Motion for React](https://motion.dev/docs/react) — **OFFICIAL DOC**. Use only if already present or justified by the implementation; motion quality comes from interaction design, not a library.
- [WebKit responsive motion guidance](https://webkit.org/blog/7551/responsive-design-for-motion/) — **FIRST-PARTY WEB GUIDANCE**. Define reduced alternatives per pattern rather than indiscriminately disabling all animation.
- [WebKit cross-document view transitions](https://webkit.org/blog/16967/two-lines-of-cross-document-view-transitions-code-you-can-use-on-every-website-today/) — **FIRST-PARTY WEB GUIDANCE**. Treat transitions as progressive enhancement and preserve routing without them.
