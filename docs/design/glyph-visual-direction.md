# Glyph visual direction

Written as a design-director audit of the rendered product, not a code review. No code was changed to produce this. Inspected live, signed out, real data, 1440px: `/`, `/explore`, `/dev/[username]`, `/p/[username]/[project]`, `/p/…/[devlog]`, `/collaborate`, `/playtests/browse`, and the `/design/dashboard`, `/design/account` fixtures standing in for `/dashboard`, `/notifications`, `/settings` (real sessions are not reachable in this environment — same limitation every phase has stated).

Milestone correction, agreed: **Architecture + UX implementation complete. Visual art direction still needs refinement.** The prior audit verified the system works — routes resolve, states are reachable, security holds, nothing overflows. It did not verify the product looks like something worth wanting to use. Those are different questions, and this document only answers the second one.

---

## 1. What currently looks weak

- **The landing page is the only page with a visual identity.** `/` has color, imagery, a mock devlog card with a real screenshot-shaped illustration, a two-tone headline, real compositional asymmetry. Every page behind sign-in-or-not — Explore, Collaborate, Playtests, a developer's own profile — drops all of that at the door and becomes black text on white with thin gray hairlines. The product has one good page and ten neutral ones.
- **Explore, Collaborate, Playtests are indistinguishable list pages.** Same shape on all three: eyebrow word → bold title → one gray sentence → hairline → repeat. A single-letter avatar tile ("P", "R", "E") is the only non-text element on the entire Explore page. Nothing in the composition tells you these are three different kinds of intent (browsing games vs. offering a role vs. offering to test) — only the words do.
- **The profile page has no anchor.** "Deep" — a small round initials circle, a name, a role list, two hairline sections, one of which is an apology ("Deep hasn't posted a devlog yet"). Nothing on the page is *this person's*. It reads as a record in a table that happens to have a name field, not as somebody's presence.
- **The devlog article has no project identity carried into it.** The project's own accent (its cover image, its badges) exists on `/p/…/[project]` and is completely gone by the time you're one click deeper on `/p/…/[devlog]` — just a small purple text link back to the project name in a metadata line, same visual weight as the date next to it. A devlog reads as a plain markdown post; nothing marks it as *this game's* devlog specifically.
- **Notifications is a column of colored dots.** No avatars, no thumbnails, no grouping beyond a flat list — every row (a follow, an application, a comment, a studio invite) has identical visual weight regardless of how different those events actually are to the person reading them.
- **Nothing outside the landing page uses color for anything but links and the primary button.** Accent purple appears exactly twice per page: link text, and the one primary CTA. Status, stage, category — all rendered in the same gray as everything else, differentiated only by a text label.
- **Horizontal space is empty, not composed.** Even after Phase L's centering fix, a 1440px viewport puts ~230px of nothing on each side of a ~770px column of hairline-separated text. The fix made the imbalance symmetrical; it didn't give the page anything to do with the room.

## 2. Why it looks weak

- **Hierarchy is declared by section order, not by visual weight.** `Section`/`SectionHeader` gives every heading on a page the same `text-h3`/600-weight treatment regardless of whether it's introducing the single most important fact on the page (a project's own title) or a footnote (a tag list). Nothing on a page is allowed to be bigger, bolder, or more present than anything else at the same nesting level — so "who am I looking at / what are they building / what happened recently" all compete at equal volume instead of stepping down in a deliberate order.
- **The system has one texture: hairline-divided rows.** `Section`, `MetadataBar`, `ProjectRow`/`DevlogRow`/`EventRow`/`JamRow`, `RelationshipList`, `NotificationsView` — nine different object types, one visual grammar. That grammar (Phase A's deliberate "no cards, no decoration, use dividers" rule) was built specifically to escape an earlier glassmorphism/card-panel excess, and it did — but it has no second gear. There is no primitive in the system whose job is "make this one thing the visual center of the page." Once the anti-slop rule removed cards, nothing replaced the function cards were serving: giving one object on the page more presence than its neighbors.
- **Imagery is used exactly once.** Cover images exist in the schema and render beautifully where present (`/p/…/emberfall-keep`'s sky photo is the single best-looking moment in the whole product) — but nothing else on that same page, and nothing on Profile, Devlog, Explore, or Collaborate, inherits or echoes it. A screenshot is treated as one field among many, not as the thing that makes a game *look like a game* instead of a spreadsheet row.
- **Color has no second job.** Phase A's rule — accent only for interaction/links/focus, never decoration — is the right rule and correctly implemented. But nothing replaced the *communicative* job color would otherwise do: a stage ("Alpha"), a role, a status, a category are all rendered as plain gray label text. The system removed decorative color and never assigned the freed-up visual budget to anything else, so those genuinely different facts all look the same.
- **Metadata and content share one typographic register.** A devlog's title, its byline, its date, and its tag list are all variations on the same small sans-serif at slightly different weights and grays. Nothing about the type itself signals "this is the work" vs. "this is a fact about the work" — the only signal is font-size, and the steps between sizes (12/13/16/20/24/32) are close enough that the page doesn't feel edited, it feels formatted.
- **The rhythm never breaks.** `heading → hairline → row → hairline → row` repeats with zero exceptions across nine different object types. A mature editorial layout breaks its own rhythm on purpose — a pull quote, a full-bleed image, a stat that's allowed to be huge — precisely at the moment the content deserves it. Glyph's primitives don't have an "allowed to be huge" mode.

## 3. What Glyph should visually feel like

A developer's page on Glyph should read like an **editorial feature about a project**, not like a record inspector for one. Concretely:

- **One clear subject per page, stated in the composition before it's stated in words.** On a project page, the game *is* the page — its image, its title, its current status lead everything else, sized and placed so a glance answers "what is this" before a single word is read. On a profile, the person's current work plays that role. On a devlog, the entry's own moment (a screenshot, a milestone number, a headline claim like "Public Alpha is out") leads; the surrounding project identity (its accent, a small persistent visual tag) should ride along quietly on every devlog under it, so the Developer → Project → Devlog chain is visible in the composition, not just the breadcrumb.
- **A visible top of the hierarchy on every page.** Whoever/whatever the page is about gets a size and a treatment nothing else on that page gets — bigger type, an image, a color chip, more surrounding space — and everything else (metadata, secondary facts, related lists) is visibly smaller and quieter, in that order, every time.
- **Color that reports state, not just links.** Stage, status, availability, category earn a small, consistent chip or accent — not a rainbow, one restrained system reused everywhere (the way `Badge`/`StatusText` tones already half-do, just not applied to the facts that actually vary page to page).
- **Imagery treated as identity, not as a field.** A cover image is the closest thing a game has to a face. It should be present, and present *consistently*, everywhere that game is referenced — its profile card, its devlog list, its jam entry, its collaboration post — the way an avatar already is for a person.
- **Density that matches intent, not just "rows separated by hairlines."** A browse page (Explore, Collaborate, Playtests) is a scanning task — it should feel like a market: denser, image-anchored, quickly comparable. An object page (a single project, a single devlog) is a reading task — it should feel like a magazine spread: fewer things, more room, deliberate pacing. Right now both feel like the same database table at two different lengths.
- **Controlled variation.** Not every page needs to break the rhythm, but the rhythm needs to be breakable — one page (the project's hero moment), one section (a devlog's cover image), one number (playtest signups, entry counts) allowed to be the loudest thing on the page when it earns it.

## 4. Concrete changes required

Each item classified **KEEP / REFINE / REWORK / REMOVE / INTRODUCE**. Nothing here has been implemented.

| # | Change | Classification |
|---|---|---|
| 1 | Flat, hairline-divided sections as the *default* page grammar | **KEEP** — correct baseline, correct anti-slop instinct, should stay the resting state most content returns to |
| 2 | Accent purple reserved for interaction/links/focus only | **KEEP** — the rule is right; what's missing is a *second*, separate visual channel (see #6), not more purple |
| 3 | `Section`/`SectionHeader` giving every heading the same weight regardless of importance | **REFINE** — needs a "lead" variant (larger, more space above/below) for the one heading per page that is the actual subject, distinct from every subordinate section heading |
| 4 | Project page (`/p/[user]/[project]`) composition | **REFINE** — closest to correct already (cover image + badges + two-column facts); needs its lead image/title treatment to visibly *outrank* its own metadata column rather than sit beside it at comparable weight |
| 5 | Profile page hero (avatar + name + facts) | **REWORK** — currently a small circle and a name at list-item scale; needs to lead the page the way the project page's cover does — larger presence, current work visually attached to the identity rather than filed under a subsection below a hairline |
| 6 | A quiet "state color" system for stage/status/category (Alpha, Open to collaborate, Looking for help, jam phase) | **INTRODUCE** — small, restrained, consistent chip treatment, extending `Badge`'s existing tone system to facts that currently render as plain gray text |
| 7 | Cover-image usage limited to the project page itself | **REWORK** — carry a small, consistent visual reference to a project's identity (not necessarily the full image — could be a thumbnail, a color, a crop) onto its devlogs, its collaboration posts, its jam entries, everywhere it's referenced today as text-only |
| 8 | Devlog article's connection to its parent project | **REFINE** — the breadcrumb and inline link are structurally correct (Phase C's own stated goal); they need more visual weight than the byline text they currently match, so the Developer → Project → Devlog chain reads at a glance, not just on click |
| 9 | Explore/Collaborate/Playtests list-row density and anchor | **REWORK** — these are scanning surfaces and should feel like one; each row needs a visual anchor (a thumbnail, a role-colored chip, something other than a single-letter circle) so three or four rows don't collapse into one paragraph of gray text |
| 10 | Notifications row treatment | **REFINE** — add the actor's avatar (data already available, per `lib/notifications/present.ts`'s actor identity) so a notification reads as "a person did something" rather than "a dot has text next to it" |
| 11 | Settings/Dashboard's plain, left-aligned, form-forward composition | **KEEP** — this is Operate mode; the flat, quiet, no-imagery treatment is correct here specifically, and should *not* receive the same treatment as Explore/Profile/Project |
| 12 | A single "lead moment" allowance in the primitive set — one section per object page permitted a larger, non-hairline treatment (image, big number, a pulled statement) | **INTRODUCE** — the one new primitive this direction actually needs; everything else above is reuse and emphasis of what exists, not new components |
| 13 | The empty horizontal margin at 1024/1440 on browse/list pages, now that it's centered | **REFINE, deferred** — once #9 gives list rows a real visual anchor (images/chips), revisit whether the centered column should widen or gain a second zone; not a fix to make blind, and explicitly not in scope until the content itself has something to put there |

No change in this document proposes: new colors beyond the existing token palette, gradients, glassmorphism, card panels, decorative backgrounds, or a departure from the flat/hairline grammar as the default. The direction is to let a small number of genuinely important moments outrank that default on purpose — not to replace it.
